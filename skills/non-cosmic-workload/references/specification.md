编写说明：
1、项目名称应与软件工作量评估送审材料中的项目名称保持一致
2、工作类型与内容属性为必选项，不能留空，工作类型共5种：配置、数据库操作、多系统联调，每种工作类型对应多个不同的内容属性，已在模板中做了自动关联。工作类型根据实际发生情况填写，不需要每种类型的工作都填写
3、每一项工作的颗粒度应尽量详细，以包含一个不可细分的完整的业务处理过程为度量标准
4、格式上，如果一条需求包含多个工作类型或工作内容，A-E列，请按需求合并单元格。F-L列，需根据具体工作详情，逐行填写。请每条工作详情分别填写内容并标注天数。详见示例；
5、K列送审人天，应填此项工作所耗费的人天。例如：多系统联调，投入4人，总共耗费20人天。那么投入人数填4，送审人天填20，不是4
6、本需求所有的非COSMIC工作内容，请填写在一张表格里
7、非COSMIC评估工作量填写完成后，请删除填写说明
8、文档命名要求为，非COSMIC评估工作量填报-项目序号XXX-需求序号YYY.xlsx（其中XXX代表项目的编号如 1、8、123 等，YYY代表需求编号）

工作类型与内容属性：
| 工作类型 | 内容属性 | 工作内容说明 |
| 配置 | 通过配置操作满足新需求 | 1）使用系统中已有功能的自动化生成代码生成的能力，发布新的接口模块等  2）不含通过界面拖拽生成报表  3）不含利用现有流程引擎即可配置新流程节点（不涉及代码开发、脚本配置） |
| 配置 | OU（组织单位）的增删改 | 1）IT系统增加使用节点，如通过配置增加一个省/租户的接入  2）单纯通过IT系统用户管理功能进行增删改、以及权限配置，则属于维护性工作，不在开发工作量范围内，设计填报模板，设置可量化的字段，明确工作量 |
| 配置 | 公共平台标准接口接入-平台侧 | IT系统中已有标准接口的接入工作，如4A、网状网、ERP集中化流程平台，公共平台侧的配合工作 |
| 配置 | 公共平台标准接口接入-接入侧 | IT系统中已有标准接口的接入工作，如4A、网状网、ERP集中化流程平台，对接侧的调测工作 |
| 配置 | 利用流程引擎与脚本配置、代码开发增加新的流程节点 | 综合利用流程引擎、脚本配置、代码开发来增加新的流程节点，不含仅通过使用已开发实现的流程配置功能界面新增、修改、删除流程节点 |
| 配置 | 系统架构升级及调整 | 对系统架构做出的配置型调整，不涉及业务流程的变更，不涉及编码开发 |
| 数据库操作 | 支撑类报表制作 | 通过sql获取数据，进行二次加工制作所需数据报表  应填报所操作的数据库表名称、字段、报表制作步骤  数据操作复杂度要求：跨3个表或字段10个以上 |
| 数据库操作 | 数据迁移 | 因业务需要，做数据库、数据表中数据的迁移，包含配合去IOE的数据迁移 |
| 数据库操作 | 数据库表维护 | 因更新字段名、库表结构变化导致的数据映射文件配置工作。  查重规则：如已填报相应开发工作则不予认可 |
| 数据库操作 | 性能调优 | 根据业务性能要求，对数据库进行一系列的调优操作 |
| 多系统联调 | 开发侧多系统联调 | 详见《多系统联调测试工作量填报及评估原则》  应详细填写以下内容：  1、联调工作内容详述、联调涉及系统、系统所属省份、需求部门  2、各联调工作内容对应的联调工作量（人天） |
| 多系统联调 | 配合侧系统调测 | 为开发侧系统提供对接联调测试服务，且该类工作量未包含在维护合同中的 |
